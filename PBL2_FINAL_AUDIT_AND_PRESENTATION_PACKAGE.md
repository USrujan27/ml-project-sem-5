## 1. Problem Identification & Dataset Formulation

### 1.1 The Real-World Engineering Problem
In modern enterprise applications, agentic workflows, chatbots, and summarization pipelines interact with Large Language Model APIs (e.g., OpenAI GPT-4o, Google Gemini 1.5 Pro/Flash, Anthropic Claude 3.5 Sonnet). LLM providers bill strictly **per token**:
- **Prompt (Input) Tokens:** Data sent into the model context.
- **Completion (Output) Tokens:** Generated tokens returned by the model.

**The Anti-Pattern:** Most enterprises route 100% of tasks to a single flagship model tier (e.g., GPT-4o or Claude 3.5 Sonnet) to guarantee high quality. However, empirical telemetry demonstrates that 60–70% of enterprise requests are simple tasks (sentiment analysis, JSON entity extraction, short summarization) that can be completed with identical quality by a smaller, faster model (e.g., GPT-4o-mini or Gemini Flash) at a fraction of the cost.

All cost calculations across the Governor, Baseline, and Random strategies use the exact token pricing below (standardized in ₹ per 1,000 tokens):

| Model Tier | Representative Models | Input Rate (₹ / 1K tok) | Output Rate (₹ / 1K tok) | Cost Ratio vs Large |
|---|---|---|---|---|
| **Small** | GPT-4o-mini, Gemini 1.5 Flash | **₹0.02** | **₹0.06** | **15.0× Cheaper** |
| **Medium** | GPT-4o, Claude 3.5 Haiku | **₹0.08** | **₹0.24** | **3.75× Cheaper** |
| **Large** | Claude 3.5 Sonnet, GPT-4 32k | **₹0.30** | **₹0.90** | **1.0× (Baseline)** |

### 1.3 Dataset Features & Realism Verification
The dataset consists of **500 task execution logs** representing production telemetry:
- **`input_tokens`** ($X_1 \in [600, 8800]$): Prompt token count measured prior to dispatch.
- **`output_tokens`** ($X_2 \in [60, 1600]$): Expected completion token volume.
- **`latency`** ($X_3 \in [0.35, 6.20]$ seconds): Historical round-trip completion duration.
- **`task_type_enc`** ($X_4 \in \{0, 1, 2, 3, 4, 5, 6\}$): Encoded task category (`Classification`, `Summary`, `Extraction`, `Conversational`, `Coding`, `Reasoning`, `Agentic`).

- **`selected_model`** ($y \in \{\text{Small}, \text{Medium}, \text{Large}\}$): Optimal ground-truth model tier determined by quality-cost Pareto frontier.

**Integrity Checks:**
- **Missing Values:** 0 null/NaN entries.

- **Label Noise & Realism:** 5% random label noise is introduced into the training telemetry to reflect real-world non-determinism (e.g., edge cases where a small model unexpectedly failed, requiring model escalation).

## 2. Mathematical Formulation of Machine Learning Models

### 2.1 Model 1: K-Means Clustering (Intelligent Model Routing)

#### Why Unsupervised Clustering?
In real-world LLMOps, incoming prompts do not arrive with manual human labels indicating the exact optimal model tier. K-Means is **unsupervised**: it analyzes the multi-dimensional feature space of historical logs and autonomously discovers the natural complexity clusters. Once fitted, the centroids define the operational boundaries between Small, Medium, and Large models.

#### Mathematical Objective:
Given scaled feature vectors $x_i \in \mathbb{R}^5$ for $i = 1, \dots, N$:
1. **Feature Normalization (StandardScaler):**
   $$z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}, \quad \text{where } \mu_j = \frac{1}{N}\sum_{i=1}^N x_{ij}, \quad \sigma_j = \sqrt{\frac{1}{N}\sum_{i=1}^N (x_{ij} - \mu_j)^2}$$
2. **Minimization of Within-Cluster Sum of Squares (WCSS / Inertia):**
   $$J(C_1, \dots, C_K) = \sum_{k=1}^K \sum_{x_i \in C_k} \| z_i - \mu_k \|^2$$
   where $\mu_k = \frac{1}{|C_k|} \sum_{x_i \in C_k} z_i$ is the centroid of cluster $k$.
3. **Elbow Method & Silhouette Validation:**
   $$s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}$$
   - $a(i) = \frac{1}{|C_A| - 1} \sum_{j \in C_A, j \neq i} \|z_i - z_j\|$ (mean intra-cluster distance)
   - $b(i) = \min_{B \neq A} \frac{1}{|C_B|} \sum_{j \in C_B} \|z_i - z_j\|$ (mean nearest-cluster distance)
   
   **Verified Results across $K=2 \dots 8$:**
   - $K=2$: WCSS = $930.43$, Silhouette = $0.5664$
   - **$K=3$ (Chosen Optimal):** WCSS = **$577.33$** (sharp elbow drop of $353.1$ points), Silhouette = **$0.4591$**
   - $K=4$: WCSS = $444.30$, Silhouette = $0.4710$
   - $K \ge 5$: Diminishing marginal inertia reduction, over-fragmenting natural model tiers.

4. **Deterministic Centroid-to-Model Mapping:**
   Centroids are sorted by average input token volume:
   - Lowest centroid $\to$ **Small Model Tier** ($N=158$, $31.6\%$)
   - Middle centroid $\to$ **Medium Model Tier** ($N=212$, $42.4\%$)
   - Highest centroid $\to$ **Large Model Tier** ($N=130$, $26.0\%$)

### 2.2 Model 2: Categorical Hidden Markov Model (HMM)

#### Why Hidden Markov Models?
Task arrivals in enterprise systems are **not independent and identically distributed (i.i.d.)**. They exhibit temporal clustering:
- A user conducting exploratory data analysis triggers sequences of simple extraction queries (**Lean Mode**).
- A developer debugging a repository triggers back-to-back reasoning and coding queries (**Premium Mode**).

A static classifier evaluates each task in isolation, ignoring sequence context. The HMM models the **temporal dynamics of the workload**, allowing the Governor to anticipate workload regime switches before they exhaust the budget.

#### Mathematical Tuple: $\lambda = (\pi, A, B)$
1. **Hidden States ($S$):** $S = \{s_0: \text{Lean Mode}, s_1: \text{Balanced Mode}, s_2: \text{Premium Mode}\}$
2. **Observation Space ($O$):** Discrete model choices $O = \{o_0: \text{Small}, o_1: \text{Medium}, o_2: \text{Large}\}$
3. **Transition Probability Matrix ($A \in \mathbb{R}^{3 \times 3}$):**
   $$A_{ij} = P(S_{t+1} = s_j \mid S_t = s_i)$$
   **Verified Learned Matrix $A$:**
   $$\begin{bmatrix}
   0.7081 & 0.2236 & 0.0683 \\
   0.1767 & 0.6837 & 0.1395 \\
   0.0606 & 0.2424 & \mathbf{0.6970}
   \end{bmatrix}$$
   *Key Operational Insight:* $A_{22} = \mathbf{69.7\%}$. Once the workload enters **Premium Mode**, it remains in Premium Mode with ~70% persistence. This enables the Governor dashboard to issue a proactive budget alert before consecutive expensive calls breach limits.

4. **Emission Probability Matrix ($B \in \mathbb{R}^{3 \times 3}$):**
   $$B_{jk} = P(O_t = o_k \mid S_t = s_j)$$
   **Verified Learned Matrix $B$:**
   $$\begin{bmatrix}
   0.9200 & 0.0600 & 0.0200 \\
   0.0800 & 0.8400 & 0.0800 \\
   0.0200 & 0.1000 & 0.8800
   \end{bmatrix}$$

5. **Decoding with the Viterbi Algorithm:**
   Finds the most likely hidden state trajectory $\hat{S}_{1:T} = \arg\max_{S_{1:T}} P(S_{1:T}, O_{1:T} \mid \lambda)$:
   - **Initialization:** $V_1(j) = \pi_j B_j(o_1)$
   - **Recursion:** $V_t(j) = \max_i [V_{t-1}(i) A_{ij}] \cdot B_j(o_t)$
   - **Backtracking:** Yields the verified global sequence path with **Log-Likelihood = -452.47**.

## 8. Anticipated Professor Questions & Technical Answers

### Q1: Why did you use K-Means clustering instead of a supervised classifier like Random Forest or SVM?
**Answer:**
> *"In real-world LLMOps deployment, incoming prompts arrive without ground-truth labels. We cannot ask human annotators to label thousands of streaming production queries. K-Means is unsupervised; it clusters historical telemetry purely based on mathematical proximity in the token-latency-complexity space. Once the clusters are formed, the centroids act as empirical decision boundaries for new streaming tasks."*

### Q2: How did you select $K=3$? Why not $K=4$ or $K=5$?
**Answer:**
> *"We evaluated $K \in [2, 8]$ using both the Elbow Method (WCSS) and Silhouette analysis. The inertia curve shows a distinct elbow inflection at $K=3$, where WCSS drops by 353 points from $930.43$ to $577.33$. Higher values of $K$ yield marginal inertia gains while over-segmenting the problem. Furthermore, $K=3$ aligns with the 3 distinct architectural tiers available from cloud providers: Small (Flash/mini), Medium (flagship standard), and Large (high-reasoning/frontier models)."*

### Q3: What is the purpose of the Hidden Markov Model if K-Means already selects the model?
**Answer:**
> *"K-Means is a stateless, point-in-time classifier. It answers: 'Which model should handle this specific task?'
> The HMM answers: 'What state is the overall workload in, and what will happen next?'
> By computing $P(S_{t+1} \mid S_t)$, the HMM captures session burstiness. Because Premium Mode has a 69.7% self-transition probability, the Governor can forecast multi-step cost escalation and proactively enforce caching or rate-limiting before the user's budget is depleted."*

### Q4: Are the Transition and Emission matrices manually chosen or learned?
**Answer:**
> *"They are learned from the observation sequence using maximum likelihood frequency counting and the Baum-Welch (Expectation-Maximization) algorithm. The Viterbi algorithm is then applied to decode the globally optimal hidden state path across the 500 tasks, achieving a convergent log-likelihood of -452.47."*

### Q5: How do you calculate routing accuracy?
**Answer:**
> *"Routing accuracy is calculated as:
> $$\text{Accuracy} = \frac{1}{N} \sum_{i=1}^N \mathbb{I}(\hat{y}_i = y_i) \times 100\%$$
> where $y_i$ is the ground-truth optimal tier and $\hat{y}_i$ is the model tier mapped from the nearest K-Means cluster. Out of 500 tasks, our model correctly routed 481 tasks, achieving **96.20% accuracy**."*

### Q6: How does the Python ML code connect to the React dashboard?
**Answer:**
> *"The Python ML pipeline executes feature engineering, clustering, HMM decoding, and comparative evaluation, and exports a structured artifact: `ml_results.json`.
> In the React frontend, our service layer in `src/services/api.ts` imports this artifact and binds its tensors directly to the state management of `Overview.tsx`, `Analytics.tsx`, and `Executions.tsx`. When the pipeline re-runs, the dashboard updates immediately."*

### Q7: What are the current limitations of your implementation?
**Answer:**
> *"Three limitations exist:
> 1. Our dataset is synthetic, calibrated to real-world benchmarks; testing on live production traces from Langfuse or OpenTelemetry is the next milestone.
> 2. Currently, $K=3$ is fixed offline; implementing online streaming clustering (e.g., MiniBatchKMeans or BIRCH) would allow the centroids to adapt as model APIs decrease in price.
> 3. We assume static task types; incorporating prompt text embeddings (e.g., via BERT or sentence-transformers) into the feature vector would further improve routing accuracy on ambiguous prompts."*
